# DEXPI 1.3 class mapping for v0.1 extraction types

## Scope and source basis

This note maps the ticket's extraction vocabulary to the DEXPI P&ID Specification 1.3 metamodel, not to Proteus XML elements. The cited HTML is the official version 1.3 reference, released June 1, 2021; the corresponding first-party repository release is tag [`V1.3.0`](https://gitlab.com/dexpi/Specification/-/tree/V1.3.0). ([DEXPI 1.3 landing page](https://dexpi.plants-and-bytes.de/))

## Recommended mappings

### Equipment

**Map `Equipment` to `Equipment.Equipment` (abstract).** Its direct supertypes are `ChamberOwner`, `NozzleOwner`, and `TaggedPlantItem`. Consequently equipment can own chambers and nozzles and inherits the full-tag fields `TagName`, `TagNamePrefix`, `TagNameSequenceNumber`, and `TagNameSuffix`; its own key field is `EquipmentDescription`, and it composes optional collections of `DryingChamber`, `GearBox`, `MotorAsComponent`, and `SprayNozzle`. Because the class is abstract, it has no class-level RDL reference or fixed `ComponentClass`; both depend on the concrete subclass. ([`Equipment.Equipment`](https://dexpi.plants-and-bytes.de/reference/Equipment/Equipment.html), [`Equipment.TaggedPlantItem`](https://dexpi.plants-and-bytes.de/reference/Equipment/TaggedPlantItem.html))

The complete **direct** subclass set in 1.3 is: `Agglomerator`, `Agitator`, `Blower`, `Burner`, `Centrifuge`, `Compressor`, `CoolingTower`, `CustomEquipment`, `Dryer`, `ElectricGenerator`, `Extruder`, `Fan`, `Feeder`, `Filter`, `HeatExchanger`, `Heater`, `Mill`, `Mixer`, `MobileTransportSystem`, `Motor`, `PackagingSystem`, `ProcessColumn`, `Pump`, `Separator`, `Sieve`, `StationaryTransportSystem`, `Turbine`, `Vessel`, `WasteGasEmitter`, and `Weigher`. ([`Equipment.Equipment` subtype list](https://dexpi.plants-and-bytes.de/reference/Equipment/Equipment.html))

For an implementation that preserves every concrete 1.3 discriminator, the deeper descendants, grouped by their immediate parent, are:

- `Agglomerator` → `CustomAgglomerator`, `ReciprocatingPressureAgglomerator`, `RotatingGrowthAgglomerator`, `RotatingPressureAgglomerator`. ([`Equipment.Agglomerator`](https://dexpi.plants-and-bytes.de/reference/Equipment/Agglomerator.html))

### CustomEquipment fallback

**Map the fallback to `Equipment.CustomEquipment`.** It inherits `CustomObject` and `Equipment`, has RDL `CUSTOM EQUIPMENT`, `ComponentClass=CustomEquipment`, and URI `http://sandbox.dexpi.org/rdl/CustomEquipment`; therefore it retains the equipment tag and description fields while allowing custom classification. ([`Equipment.CustomEquipment`](https://dexpi.plants-and-bytes.de/reference/Equipment/CustomEquipment.html))

### Valve

**Do not create an official-class claim for a generic `Valve`: DEXPI 1.3 has no class named `Valve`.** The official `PipingComponent` direct subtypes split this domain into `OperatedValve`, `CheckValve`, and `SafetyValveOrFitting`; the last is intentionally broader than valves. All three inherit the abstract `PipingComponent`, whose key inherited fields are `FluidCode`, `OnHold`, `PipingClassArtefact`, and `PressureTestCircuitNumber`. ([`Piping.PipingComponent`](https://dexpi.plants-and-bytes.de/reference/Piping/PipingComponent.html), [official `Piping` package class index](https://dexpi.plants-and-bytes.de/reference/Piping/index.html))

- `Piping.OperatedValve`: RDL `OPERATED VALVE`, `ComponentClass=OperatedValve`, URI `http://data.posccaesar.org/rdl/RDS11141590`; direct subtypes are `AngleBallValve`, `AngleGlobeValve`, `AnglePlugValve`, `AngleValve`, `BallValve`, `ButterflyValve`, `CustomOperatedValve`, `GateValve`, `GlobeValve`, `NeedleValve`, `PlugValve`, and `StraightwayValve`. Key own fields are `HeatTracingType`, `HeatTracingTypeRepresentation`, `InsulationThickness`, `InsulationType`, `LowerLimitHeatTracingTemperature`, `NumberOfPorts`, `Operation`, `PipingClassCode`, `PipingComponentName`, and `PipingComponentNumber`. ([`Piping.OperatedValve`](https://dexpi.plants-and-bytes.de/reference/Piping/OperatedValve.html))
- `Piping.CheckValve`: RDL `CHECK VALVE`, `ComponentClass=CheckValve`, URI `http://data.posccaesar.org/rdl/RDS292229`; direct subtypes are `CustomCheckValve`, `GlobeCheckValve`, and `SwingCheckValve`. Its key own fields are the same piping/tracing fields as operated valves except `NumberOfPorts` and `Operation`. ([`Piping.CheckValve`](https://dexpi.plants-and-bytes.de/reference/Piping/CheckValve.html))
- `Piping.SafetyValveOrFitting`: RDL `SAFETY VALVE OR FITTING`, `ComponentClass=SafetyValveOrFitting`, URI `http://sandbox.dexpi.org/rdl/SafetyValveOrFitting`; direct subtypes are `BreatherValve`, `CustomSafetyValveOrFitting`, `FlameArrestor`, `RuptureDisc`, `SpringLoadedAngleGlobeSafetyValve`, and `SpringLoadedGlobeSafetyValve`. Key own fields are `FlowInPipingClassCode`, `FlowOutPipingClassCode`, `LocationRegistrationNumber`, `PositionNumber`, `SetPressureHigh`, and `SetPressureLow`. ([`Piping.SafetyValveOrFitting`](https://dexpi.plants-and-bytes.de/reference/Piping/SafetyValveOrFitting.html))

Every listed concrete valve subtype has its own official RDL/`ComponentClass` entry; the class name is the `ComponentClass` in this valve subtree. ([official `Piping` package class index](https://dexpi.plants-and-bytes.de/reference/Piping/index.html))

### In/out off-page connectors

**Map `in-off-page-connector` to `Piping.FlowInPipeOffPageConnector` and `out-off-page-connector` to `Piping.FlowOutPipeOffPageConnector`.** Both inherit abstract `PipeOffPageConnector`; flow-in also inherits `PipingSourceItem`, while flow-out also inherits `PipingTargetItem`. The base composes optional `ConnectorReference`; the concrete RDL/`ComponentClass` pairs are `FLOW IN PIPE OFF PAGE CONNECTOR` / `FlowInPipeOffPageConnector` / `http://sandbox.dexpi.org/rdl/FlowInPipeOffPageConnector` and `FLOW OUT PIPE OFF PAGE CONNECTOR` / `FlowOutPipeOffPageConnector` / `http://sandbox.dexpi.org/rdl/FlowOutPipeOffPageConnector`. ([`Piping.PipeOffPageConnector`](https://dexpi.plants-and-bytes.de/reference/Piping/PipeOffPageConnector.html), [`FlowInPipeOffPageConnector`](https://dexpi.plants-and-bytes.de/reference/Piping/FlowInPipeOffPageConnector.html), [`FlowOutPipeOffPageConnector`](https://dexpi.plants-and-bytes.de/reference/Piping/FlowOutPipeOffPageConnector.html))

### ActuatingSystemComponent / control-valve assembly

**`ActuatingSystemComponent` is the Proteus element family, not a DEXPI 1.3 metamodel class; model the assembly as `Instrumentation.ActuatingSystem`.** `ActuatingSystem` inherits `CustomAttributeOwner` and `TechnicalItem`, has fields `ActuatingSystemNumber` and `TypicalInformation`, and composes at most one each of `ControlledActuator`, `OperatedValveReference`, and `Positioner`, plus any number of `CustomActuatingSystemComponent`. Its RDL/`ComponentClass`/URI are `ACTUATING SYSTEM` / `ActuatingSystem` / `http://sandbox.dexpi.org/rdl/ActuatingSystem`. ([`Instrumentation.ActuatingSystem`](https://dexpi.plants-and-bytes.de/reference/Instrumentation/ActuatingSystem.html), [official `Instrumentation` package class index](https://dexpi.plants-and-bytes.de/reference/Instrumentation/index.html))

For the controlled-valve link, `OperatedValveReference` has optional `Valve: OperatedValve` and `SubTagName`; it uses RDL/`ComponentClass` `OPERATED VALVE REFERENCE` / `OperatedValveReference`. `ControlledActuator` carries `DeviceTypeName`, `FailAction`, `FailActionRepresentation`, and `SubTagName`, with RDL/`ComponentClass` `CONTROLLED ACTUATOR` / `ControlledActuator`. ([`Instrumentation.OperatedValveReference`](https://dexpi.plants-and-bytes.de/reference/Instrumentation/OperatedValveReference.html), [`Instrumentation.ControlledActuator`](https://dexpi.plants-and-bytes.de/reference/Instrumentation/ControlledActuator.html))

### SignalLine

**Map `SignalLine` to `Instrumentation.SignalLineFunction`.** It inherits `SignalConveyingFunction` and has RDL/`ComponentClass`/URI `SIGNAL LINE FUNCTION` / `SignalLineFunction` / `http://sandbox.dexpi.org/rdl/SignalLineFunction`. Through its parent it has optional `Source`, `Target`, `PortStatus`, `SignalConveyingType`, `SignalPointNumber`, and `SignalProcessControlFunctions`. ([`Instrumentation.SignalLineFunction`](https://dexpi.plants-and-bytes.de/reference/Instrumentation/SignalLineFunction.html), [`Instrumentation.SignalConveyingFunction`](https://dexpi.plants-and-bytes.de/reference/Instrumentation/SignalConveyingFunction.html))

### MainProcessLine

**DEXPI 1.3 has no class named `MainProcessLine`; map a line-level extraction object to `Piping.PipingNetworkSystem`, with child `PipingNetworkSegment` objects and `Pipe` connections.** `PipingNetworkSystem` inherits `CustomAttributeOwner` and `TechnicalItem`, composes `Segments[*]`, and has RDL/`ComponentClass`/URI `PIPING NETWORK SYSTEM` / `PipingNetworkSystem` / `http://data.posccaesar.org/rdl/RDS270359`. Its useful v0.1 fields include `LineNumber`, `FluidCode`, `PipingClassCode`, nominal-diameter representations/standard, insulation and heat-tracing fields, and `PipingNetworkSystemGroupNumber`. ([`Piping.PipingNetworkSystem`](https://dexpi.plants-and-bytes.de/reference/Piping/PipingNetworkSystem.html), [official `Piping` package class index](https://dexpi.plants-and-bytes.de/reference/Piping/index.html))

If extraction granularity is one uninterrupted graphical piece rather than one identified line system, use `Piping.Pipe`, which inherits `CustomAttributeOwner` and `PipingConnection`; if it is one bounded segment containing pipes and components, use `PipingNetworkSegment` (`PIPING NETWORK SEGMENT`, `ComponentClass=PipingNetworkSegment`, URI `http://data.posccaesar.org/rdl/RDS267704`). ([`Piping.Pipe`](https://dexpi.plants-and-bytes.de/reference/Piping/Pipe.html), [`Piping.PipingNetworkSegment`](https://dexpi.plants-and-bytes.de/reference/Piping/PipingNetworkSegment.html))

### Instrument

**Map the generic P&ID instrument/function bubble to `Instrumentation.ProcessInstrumentationFunction`, not to a class named `Instrument` (none exists in the 1.3 package index).** It inherits `CustomAttributeOwner`, `SignalConveyingFunctionSource`, `SignalConveyingFunctionTarget`, and `TechnicalItem`; its RDL/`ComponentClass`/URI are `PROCESS INSTRUMENTATION FUNCTION` / `ProcessInstrumentationFunction` / `http://sandbox.dexpi.org/rdl/ProcessInstrumentationFunction`. ([`Instrumentation.ProcessInstrumentationFunction`](https://dexpi.plants-and-bytes.de/reference/Instrumentation/ProcessInstrumentationFunction.html), [official `Instrumentation` package class index](https://dexpi.plants-and-bytes.de/reference/Instrumentation/index.html))

The instrument “tag” should be stored in `ProcessInstrumentationFunctionNumber`; category/modifier/function letters belong in `ProcessInstrumentationFunctionCategory`, `ProcessInstrumentationFunctionModifier`, and `ProcessInstrumentationFunctions`. Other typical fields are `DeviceInformation`, `Location`, `PanelIdentificationCode`, `TypicalInformation`, `VendorCompanyName`, `VotingSystemRepresentation`, `GmpRelevance`, `GuaranteedSupplyFunction`, `QualityRelevance`, and `SafetyRelevanceClass`. ([`Instrumentation.ProcessInstrumentationFunction`](https://dexpi.plants-and-bytes.de/reference/Instrumentation/ProcessInstrumentationFunction.html))

Do not reuse equipment `TagName` for this mapping: `TagName` is defined by `Equipment.TaggedPlantItem`, whereas `ProcessInstrumentationFunction` uses its own number/category/modifier/function attributes. Physical subcomponents such as `Transmitter` use `SubTagName` and `DeviceTypeName`. ([`Equipment.TaggedPlantItem`](https://dexpi.plants-and-bytes.de/reference/Equipment/TaggedPlantItem.html), [`Instrumentation.Transmitter`](https://dexpi.plants-and-bytes.de/reference/Instrumentation/Transmitter.html))

### SpectacleBlind, Reducer, Flange

- **`SpectacleBlind`: no exact class exists in DEXPI 1.3.** Use `Piping.LineBlind` for the general function of blinding a process stream (inherits `PipeFitting`; RDL/`ComponentClass`/URI `LINE BLIND` / `LineBlind` / `http://data.posccaesar.org/rdl/RDS280034`). Use `Piping.PipeFlangeSpade` only when the recognized symbol specifically denotes the handled solid plate/spade described by that class (inherits `PipeFitting`; `PIPE FLANGE SPADE` / `PipeFlangeSpade` / `http://data.posccaesar.org/rdl/RDS472679`). ([official `Piping` package class index](https://dexpi.plants-and-bytes.de/reference/Piping/index.html), [`Piping.LineBlind`](https://dexpi.plants-and-bytes.de/reference/Piping/LineBlind.html), [`Piping.PipeFlangeSpade`](https://dexpi.plants-and-bytes.de/reference/Piping/PipeFlangeSpade.html))
- **`Reducer` → `Piping.PipeReducer`.** It inherits `PipeFitting`; RDL/`ComponentClass`/URI are `PIPE REDUCER` / `PipeReducer` / `http://data.posccaesar.org/rdl/RDS416294`. It also inherits the pipe-fitting fields for tracing, insulation, piping class, component name, and component number. ([`Piping.PipeReducer`](https://dexpi.plants-and-bytes.de/reference/Piping/PipeReducer.html), [`Piping.PipeFitting`](https://dexpi.plants-and-bytes.de/reference/Piping/PipeFitting.html))
- **`Flange` → `Piping.Flange`.** It inherits `PipeFitting`; RDL/`ComponentClass`/URI are `FLANGE` / `Flange` / `http://data.posccaesar.org/rdl/RDS13307654`, plus the inherited pipe-fitting fields. ([`Piping.Flange`](https://dexpi.plants-and-bytes.de/reference/Piping/Flange.html), [`Piping.PipeFitting`](https://dexpi.plants-and-bytes.de/reference/Piping/PipeFitting.html))

### Nozzle

**Map `Nozzle` to `Equipment.Nozzle`.** It inherits `ActuatingElectricalLocation`, `CustomAttributeOwner`, `PipingNodeOwner`, `PipingSourceItem`, `PipingTargetItem`, and `SensingLocation`; its RDL/`ComponentClass`/URI are `NOZZLE` / `Nozzle` / `http://data.posccaesar.org/rdl/RDS415214`. Key fields are `SubTagName`, the nominal-pressure numerical/full/type representations, `NominalPressureStandard`, and optional `Chamber`. ([`Equipment.Nozzle`](https://dexpi.plants-and-bytes.de/reference/Equipment/Nozzle.html))

The requested nozzle tag is specifically `SubTagName` (RDL assignment class `SUB TAG NAME ASSIGNMENT CLASS`, name `SubTagNameAssignmentClass`), not the equipment `TagName`; nozzles are composed under a `NozzleOwner`, whose only 1.3 subtype is `Equipment`. ([`Equipment.Nozzle`](https://dexpi.plants-and-bytes.de/reference/Equipment/Nozzle.html), [`Equipment.NozzleOwner`](https://dexpi.plants-and-bytes.de/reference/Equipment/NozzleOwner.html))

## v0.1 modeling consequences

1. Keep extraction names as API aliases, but persist the official package/class discriminator separately; this is necessary for `SignalLine` → `SignalLineFunction`, `MainProcessLine` → `PipingNetworkSystem`, and `Reducer` → `PipeReducer`. ([`SignalLineFunction`](https://dexpi.plants-and-bytes.de/reference/Instrumentation/SignalLineFunction.html), [`PipingNetworkSystem`](https://dexpi.plants-and-bytes.de/reference/Piping/PipingNetworkSystem.html), [`PipeReducer`](https://dexpi.plants-and-bytes.de/reference/Piping/PipeReducer.html))
2. Represent generic `Valve` as an application-side union/base over `OperatedValve`, `CheckValve`, and the valve members of `SafetyValveOrFitting`; do not serialize or describe `Valve` as an official DEXPI 1.3 class. ([`PipingComponent`](https://dexpi.plants-and-bytes.de/reference/Piping/PipingComponent.html), [official `Piping` package class index](https://dexpi.plants-and-bytes.de/reference/Piping/index.html))
3. Represent a control valve as an `OperatedValve` plus an `ActuatingSystem` whose `OperatedValveReference.Valve` points to it; do not collapse the assembly into an alleged `ActuatingSystemComponent` metamodel class. ([`ActuatingSystem`](https://dexpi.plants-and-bytes.de/reference/Instrumentation/ActuatingSystem.html), [`OperatedValveReference`](https://dexpi.plants-and-bytes.de/reference/Instrumentation/OperatedValveReference.html))
4. Keep full equipment tags, instrument function numbers, and nozzle/component subtags as distinct fields because the specification assigns them to different classes and RDL assignment classes. ([`TaggedPlantItem`](https://dexpi.plants-and-bytes.de/reference/Equipment/TaggedPlantItem.html), [`ProcessInstrumentationFunction`](https://dexpi.plants-and-bytes.de/reference/Instrumentation/ProcessInstrumentationFunction.html), [`Nozzle`](https://dexpi.plants-and-bytes.de/reference/Equipment/Nozzle.html))
