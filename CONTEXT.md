# DEXPI 1.3 in-memory model

Python library that holds a DEXPI P&ID 1.3 conceptual model in memory. It is not a drawing, not a NetworkX graph, and not a Proteus XML document.

## Language

**ConceptualModel**:
The DEXPI 1.3 information model of a P&ID: typed plant items, piping, instrumentation, and the references between them. No graphics.
_Avoid_: drawing, graph, XML, diagram file

**PlantItem**:
A typed object in the ConceptualModel (equipment, valve, nozzle, piping component, instrument, connector).
_Avoid_: Entity, node, shape

**DEX_ID**:
Required extraction identifier on every in-memory object (`dex_id: str`). It is not the DEXPI instance `id`.
_Avoid_: extraction-id as the DEXPI `id`, graph id used as DEXPI `id`

**id**:
Frozen string UUID generated by this library for each DEXPI instance (same wire shape as pyDEXPI `id`).
_Avoid_: using DEX_ID as `id`; a separate Python `UUID` type in the public field

**CustomEquipment**:
The DEXPI class used when the extraction type has no matching equipment subclass.
_Avoid_: Tank as a generic fallback

**ActuatingSystem**:
The DEXPI 1.3 class for a controlled-valve assembly: it composes `ControlledActuator`, `OperatedValveReference`, and optional `Positioner`.
_Avoid_: ActuatingSystemComponent as a DEXPI class (that is a Proteus element family)

**ActuatingFunction**:
The DEXPI 1.3 loop function for a control valve. A `SignalConveyingFunction` attaches here via `Source`/`Target`, not to `ActuatingSystem`.
_Avoid_: attaching a signal directly to ActuatingSystem or ControlledActuator

**PipingNetworkSystem**:
The DEXPI line object. It composes `PipingNetworkSegment` objects. `lineNumber` is optional and not unique in the model.
_Avoid_: MainProcessLine as a DEXPI class; 1:1 lineNumber uniqueness as a model rule

**MainProcessLine**:
Extraction-time name for a process line. In this library it is a `PipingNetworkSystem`.
_Avoid_: a DEXPI class named MainProcessLine

**PipingNetworkSegment**:
A stretch of a `PipingNetworkSystem`, identified by optional `segmentNumber`. It composes `items` and `connections`.
_Avoid_: treating a segment as the whole line; using lineNumber as the segment id

**PipeOffPageConnector**:
A segment item (`FlowInPipeOffPageConnector` or `FlowOutPipeOffPageConnector`) that may sit in `items` while `sourceItem`/`targetItem` reference it or an external nozzle.
_Avoid_: a connector bag on the system; OPC as only an endpoint with no item

**SignalLine**:
An extraction-time signal connection. In DEXPI 1.3 it maps to `SignalConveyingFunction` (a concrete class), which references `ProcessInstrumentationFunction` or `ActuatingFunction` via `Source`/`Target`. The signal-vs-measuring distinction (`SignalLineFunction` vs `MeasuringLineFunction`) is not extracted.
_Avoid_: piping class for signals; a DEXPI class named SignalLine; instantiating `SignalLineFunction`/`MeasuringLineFunction` in v0.1; asserting signal vs measuring

**ProcessInstrumentationFunction**:
The DEXPI 1.3 class for a P&ID instrument/function bubble. Its tag lives in `ProcessInstrumentationFunctionNumber` (plus Category/Modifier/Functions), not equipment `TagName`. v0.1 has no `Transmitter` or `PrimaryElement`.
_Avoid_: Instrument as a DEXPI class name; Transmitter/PrimaryElement as v0.1 classes

**ProcessControlFunction**:
A DEXPI 1.3 subtype of `ProcessInstrumentationFunction` for a control/safeguarding system bubble (`ComponentClass` `ProcessControlFunction`). It is a function, not `Equipment`, even when extraction labels it "equipment".
_Avoid_: control/safeguarding system as Equipment

**Entity**:
An extraction-time object from the ML pipeline, with attributes and a graph id. Outside this library’s v0.1 API.
_Avoid_: using Entity as a DEXPI class name
